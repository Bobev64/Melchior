# MMC5983MA SPI library

Based on `datasheets/mmc5983.pdf` (MEMSIC Rev A). Sources:
`Core/Inc/mmc5983.h` and `Core/Src/mmc5983.c`.

## Features

- Product ID verification (`0x30` at register `0x2F`).
- Software reset and OTP-ready check.
- Single-shot magnetic and temperature measurements, with bounded data-ready polling.
- All seven magnetic output bytes read in one SPI transaction. X/Y/Z are
  unpacked as unsigned 18-bit offset-binary values, **not signed 16-bit data**.
- Nominal zero-field output: 131072; sensitivity: 16384 counts/gauss.
- Fields in microtesla (`uT`): `(raw - 131072) * 100 / 16384`.
- Approximate die temperature in Celsius: `raw * 0.8 - 75`.
- Automatic SET/RESET enabled by default, plus manual SET/RESET commands.
- Raw counts, fixed-point printing fields, HAL status, last sensor status, and
  possible saturation indication (`at_rail`).

This is not a calibrated compass/heading solution. Hard-iron and soft-iron
calibration, tilt compensation, and SET/RESET paired offset cancellation are
not implemented. Automatic SET/RESET conditions the sensor; it is not a
replacement for application-level magnetic calibration.

## Configuration

After `MMC5983_AssignSPI`, set `dev.config`, then call `MMC5983_Init`:

```c
MMC5983_t mag;
MMC5983_AssignSPI(&mag, &hspi2, MAG_CS_GPIO_Port, MAG_CS_Pin);
mag.config.bandwidth = MMC5983_BW_100HZ;
mag.config.automatic_set_reset = true;
mag.config.spi_timeout_ms = 100U;
mag.config.measurement_timeout_ms = 50U;
/* This project keeps SPI2 in mode 0 for all sensors. */
MMC5983_Status_t status = MMC5983_Init(&mag);
```

Bandwidth options are 100/200/400/800 Hz, corresponding to measurement times
of 8/4/2/0.5 ms. These are filter bandwidths, **not the polling/sample rate**.
`main.c` takes one magnetic and one temperature sample per loop, approximately
once every 500 ms plus the other sensors' conversion/output time.

Re-run `Init` after changing bandwidth or automatic SET/RESET. Timeouts can be
changed between reads. Allow sufficient measurement timeout; default 50 ms
covers all bandwidths. Outputs are only updated on success.

Manual `MMC5983_Reset` is a magnetic RESET pulse, not a software chip reset.
It reverses sensor polarity. Perform `MMC5983_Set` again before using normal
positive-polarity field conversions.

## Shared SPI bus

The datasheet describes idle-high SCK, falling-edge data changes and rising-edge
sampling: **SPI mode 3**, 4-wire, MSB-first, 8-bit data, at most 10 MHz.
The library does not reconfigure SPI or provide bus locking.

At the user's request, `main.c` keeps SPI2 in **mode 0** for MMC5983 as well as
the other sensors; there is no mode switching. The /32 prescaler is unchanged.
Mode-0 operation should be verified on hardware because the datasheet describes
mode-3 timing. No concurrent interrupt/DMA SPI access may occur; callers must
serialize transactions on the shared bus.

## SWV board verification

Enable ITM stimulus port 0. Initialization prints the ID, status and selected
settings. Successful reads print lines like the following (illustrative values):

```text
MMC5983 product ID: 0x30 (expected 0x30), init status=0, HAL=0
MMC5983 field [uT]: X=12.34 Y=-8.56 Z=40.12 (raw=...,...,...)
MMC5983 temperature: 21.00 C (raw=120, approximate 0.8 C/LSB)
```

Temperature is coarse die temperature, not a precision room-temperature
reference; displaying two decimals does not imply 0.01 C accuracy.

Rotate the board away from magnets and steel objects: axis readings should
change with orientation. Earth's field magnitude is commonly around 25-65 uT,
but PCB currents, ferrous materials, nearby magnets and sensor offset can alter
measurements substantially. The nominal axis range is +/-800 uT. A rail warning
means an axis is exactly at an ADC endpoint; investigate magnetic interference
or communication if readings remain there. Zero field is near raw 131072,
not raw zero.

Status codes: 0 success, 1 invalid argument/config, 2 not initialized, 3 SPI
error, 4 wrong product ID, 5 data-ready/OTP timeout. HAL status is printed
separately. Physical sensor operation must be verified on the board.

## Host tests

The mock-HAL test verifies ID/OTP initialization, bit packing including the
low two bits of each axis, zero/full-scale conversions, temperature conversion,
all bandwidths, manual SET/RESET, SPI errors, output preservation, and polling
timeouts including tick wraparound.

From the repository root with GCC:

```sh
gcc -std=c11 -Wall -Wextra -Werror -Itests/stubs -ICore/Inc \
    Core/Src/mmc5983.c tests/test_mmc5983.c -o /tmp/test_mmc5983
/tmp/test_mmc5983
```

Or in a Visual Studio x64 Native Tools Command Prompt:

```bat
cl /nologo /std:c11 /W4 /Itests/stubs /ICore/Inc Core/Src/mmc5983.c tests/test_mmc5983.c /Fo%TEMP%\ /Fe%TEMP%\test_mmc5983.exe
%TEMP%\test_mmc5983.exe
```

Do not put `tests/stubs` in firmware include paths.
